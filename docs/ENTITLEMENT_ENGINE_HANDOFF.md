# Commercial entitlement engine handoff

This checkpoint is **local source and emulator evidence only**. The development Firebase project still runs the previous backend. Do not deploy this change as a partial commercial release. Read [the canonical contract](COMMERCIAL_CONTRACT_V1.md) before extending it.

## Implemented locally

- `packages/core/src/commercial.ts` holds a versioned development catalog, legacy `customer`/`professional` mapping, stable capability resolution, permanent Company/Pro Demo limits, paid grace/read/export behavior, anniversary and event calculations, an ordered/idempotent provider-neutral event model, and coverage-aware cleanup eligibility.
- Firebase Account bootstrap creates Company Demo only when a subscription is absent. Existing development subscriptions are left intact. `switchDemoType` keeps all Company records and parks unselected Companies in Company Demo.
- Authenticated status callables expose the current plan/tier, Demo choice, cadence, price version, paid-through/grace dates, cancellation and downgrade state, seats, coverage source, hosted-ending date, capabilities and published-count over-limit indicators without exposing billing secrets.
- Trusted Functions enforce Company creation limits, block Demo invitations and publication (legacy and staged schema), and validate publication entity limits against resolved capabilities. Windows authoring fetches capabilities from the trusted Function on every operation and enforces Company-scoped create/restore limits below React. SDS import remains available in Demo.
- Trusted, non-callable `commercial-admin.ts` applies synthetic billing events. It materializes Pro-seat Manager permissions for all current and future covered Companies, removes inherited access on seat removal, and preserves ordinary direct membership when applicable. It marks excess Demo Companies as ending on paid Company selection. Its explicit Pro-to-Company takeover transaction establishes the client's Administrator and removes inherited Pro access without copying or deleting business data.
- Emulator rules tests verify that an added Pro seat can read a covered Company's published Chemical Product and private SDS, and that seat removal immediately revokes both reads.
- A paid Company subscription can attach to an uncovered existing Company through a trusted audited transaction when that Company already has an Administrator and the purchaser is its Administrator or HAZCOM Manager. This leaves the purchaser's Company role unchanged.
- A scheduled Pro-to-Company downgrade retains the expressly selected Company only when the renewal event arrives at the paid-through boundary. Other Companies enter the 14-day export window without data deletion. Future-dated events cannot be applied early by the trusted adapter.
- `cleanupExpiredCompanyInEmulator` is deliberately guarded to a `demo-` Firebase emulator project. It transactionally claims only the coverage-owned Company after its export deadline, audits the claim, deletes its Storage objects and Firestore copy, and records completion. It is idempotent and refuses a Company whose coverage has transferred. This is a local proof, not a deployable production cleanup worker.
- `packages/sync/src/backup.js` exports Company-owned SQLite records, ownership/link tables, soft-delete and authoring history, and SDS bytes into a versioned, hashed package. It restores to an independent fresh SQLite database only after manifest and SDS checks; the batch is atomic. This is a Node/dev foundation, not a deployed cloud-backup delivery service.
- `apps/windows/src/data/backup.ts` exposes a native-app service call that exports that same package from the active Company's SQLite/SDS workspace. It rechecks authenticated Manager/Administrator access and authoritative `canExportBackup` before and after export, so the service is available during grace/export even while authoring is paused. No backup dialog or file-save UI is part of this task.
- `packages/core/src/backup-delivery.ts` defines size-aware attachment/link selection and scoped, expiring, one-use verification/download tokens. Its in-memory transport checks the verified Company backup address and coverage state, attaches small packages, and delivers large packages through short-lived links. A test sends a full versioned package through the mock link and restores it into a fresh SQLite database. It does not send production email or store backup packages in the cloud.
- A trusted backup-email service stores a pending address and token hash, uses an injected development outbox, and makes the new address authoritative only after token confirmation. The email alone grants no Account or Membership.

## Data/authority details

Commercial plan, cadence, Company role, and capabilities are separate. Company coverage is recorded at `companies/{id}/coverage/current` and subscriptions; membership is an access role, not a payer. New commercial subscriptions track `coveredCompanyIds`, `seatIds`, version, and audit event IDs. Existing legacy subscriptions without these fields continue through the compatible resolver. No client-callable path accepts billing events; the adapter must authenticate a future provider before invoking the trusted transition. One active coverage source is enforced by the current coverage document and transactional takeover.

The Pro-seat membership document carries `proTeamSubscriptionId` as a derived access index, separate from a direct Company role. Firestore and Storage continue to read the materialized membership. Seat removal restores a saved direct membership or deletes only the derived index. Pro seats may manage linked client Members under paid coverage but cannot create Administrators or change Company settings. The original zero-Administrator Pro client pattern remains supported.

## Validation performed

`npm test` (core 9, sync 8, authoring 9, SQLite schema), `npm run test:firebase` (16 emulator tests), `npm run build`, Firebase Functions build, and Windows `cargo check` passed during this task. The test suite exercised Demo bootstrap, Company limit, Demo publication/invite denial, Pro Demo switching and parking, per-Company Demo limits, synthetic paid transition, Pro seat addition/removal and future-Company inheritance, Pro client Member invitations, invited Company Manager authoring without a paid personal plan, paid coverage for an existing Company without role mutation, audited takeover, Pro client release, scheduled downgrade, payment recovery before cleanup, emulator-only coverage cleanup including published SDS deletion, legacy paid publication, local authoring and synthetic paid-tier limits/SDS, backup round-trip, tamper rejection, and mock backup delivery. Do not infer a production deployment from these tests.

## Work still required before live commercial deployment

- Pro Company creation stores its contact email as an unverified backup address; an outbox-backed verification service can make a new address authoritative. Initial-email verification is not yet enforced, and backup request/download delivery has no cloud endpoint or production email transport.
- Scheduled downgrade transitions when a trusted renewal event arrives, but a general period-end scheduler and a production-safe cleanup worker are not implemented. The local cleanup proof is hard-guarded to demo emulators; it must not run against real development Companies. Hosted read still relies on membership/physical cleanup rather than a precise rule-level time cutoff.
- Upgrade and extra-seat events record provider-neutral proration quotes from the term dates and snapshotted development prices. No provider-invoice adapter, subscription ledger reconciliation, or webhook authentication exists. Real prices and paid Company tier ceilings need product decisions.
- Materialized Pro-seat access needs further tests for ordinary-membership overlap, transactional limits at larger team/company combinations, transfer races, and revision/SDS reads after seat removal. New Pro Company backup/contact email enforcement remains outstanding.
- The backup importer is a fresh-database Node/dev path. Native Windows import, authenticated cloud backup delivery to an email holder without an Account, and transactional activation of a restored cloud backup are separate work.

The frozen branch `frozen/commercial-entitlement-v1-2026-09-25` records this validated local/emulator foundation. It is not a claim that billing, production email, cloud backup delivery, or cloud cleanup have been deployed. Never repoint this or any earlier frozen branch.
