# Commercial entitlement engine handoff

This checkpoint is **local source and emulator evidence only**. The development Firebase project still runs the previous backend. Do not deploy this change as a partial commercial release. Read [the canonical contract](COMMERCIAL_CONTRACT_V1.md) before extending it.

## Implemented locally

- `packages/core/src/commercial.ts` holds a versioned development catalog, legacy `customer`/`professional` mapping, stable capability resolution, permanent Company/Pro Demo limits, paid grace/read/export behavior, anniversary and event calculations, an ordered/idempotent provider-neutral event model, and coverage-aware cleanup eligibility.
- Firebase Account bootstrap creates Company Demo only when a subscription is absent. Existing development subscriptions are left intact. `switchDemoType` keeps all Company records and parks unselected Companies in Company Demo.
- Authenticated status callables expose the current plan/tier, Demo choice, cadence, price version, paid-through/grace dates, cancellation and downgrade state, seats, coverage source, hosted-ending date, capabilities and published-count over-limit indicators without exposing billing secrets.
- Trusted Functions enforce Company creation limits, block Demo invitations and publication (legacy and staged schema), and validate publication entity limits against resolved capabilities. Windows authoring fetches capabilities from the trusted Function on every operation and enforces Company-scoped create/restore limits below React. SDS import remains available in Demo.
- Trusted, non-callable `commercial-admin.ts` applies synthetic billing events. It materializes Pro-seat Manager permissions for all current and future covered Companies, removes inherited access on seat removal, and preserves ordinary direct membership when applicable. It marks excess Demo Companies as ending on paid Company selection. Its explicit Pro-to-Company takeover transaction establishes the client's Administrator and removes inherited Pro access without copying or deleting business data.
- Emulator rules tests verify that an added Pro seat can read a covered Company's published Chemical Product and private SDS, and that seat removal immediately revokes both reads.
- A paid Company subscription can attach to an uncovered existing Company through a trusted audited transaction when that Company already has an Administrator and the purchaser is its Administrator or HAZCOM Manager. This leaves the purchaser's Company role unchanged.
- A scheduled Pro-to-Company downgrade retains the expressly selected Company only when the renewal event arrives at the paid-through boundary. Other Companies enter the 14-day export window without data deletion. Future-dated events cannot be applied early by the trusted adapter.
- `cleanupExpiredCompanyInEmulator` is deliberately guarded to a `demo-` Firebase emulator project. It transactionally claims only the coverage-owned Company after its export deadline, audits the claim, deletes its Storage objects and Firestore copy, and records completion. It is idempotent and refuses a Company whose coverage has transferred. This is a local proof, not a deployable production cleanup worker.
- `packages/sync/src/backup.js` exports Company-owned SQLite records, ownership/link tables, soft-delete and authoring history, and SDS bytes into a versioned, hashed package. It restores to an independent fresh SQLite database only after manifest and SDS checks; the batch is atomic. This is a Node/dev foundation, not a deployed cloud-backup delivery service.
- `apps/windows/src/data/backup.ts` exposes a native-app service call that exports that same package from the active Company's SQLite/SDS workspace. It rechecks authenticated Manager/Administrator access and authoritative `canExportBackup` before and after export, so the service is available during grace/export even while authoring is paused. The Windows workspace panel now exposes Company backup export and restore into distinct selectable workspaces.
- `packages/core/src/backup-delivery.ts` defines size-aware attachment/link selection and scoped, expiring, one-use verification/download tokens. Its in-memory transport checks the verified Company backup address and coverage state, attaches small packages, and delivers large packages through short-lived links. A test sends a full versioned package through the mock link and restores it into a fresh SQLite database. It does not send production email or store backup packages in the cloud.
- A trusted backup-email service stores a pending address and token hash, uses an injected development outbox, and makes the new address authoritative only after token confirmation. The email alone grants no Account or Membership.

## Data/authority details

Commercial plan, cadence, Company role, and capabilities are separate. Company coverage is recorded at `companies/{id}/coverage/current` and subscriptions; membership is an access role, not a payer. New commercial subscriptions track `coveredCompanyIds`, `seatIds`, version, and audit event IDs. Existing legacy subscriptions without these fields continue through the compatible resolver. No client-callable path accepts billing events; the adapter must authenticate a future provider before invoking the trusted transition. One active coverage source is enforced by the current coverage document and transactional takeover.

The Pro-seat membership document carries `proTeamSubscriptionId` as a derived access index, separate from a direct Company role. Firestore and Storage continue to read the materialized membership. Seat removal restores a saved direct membership or deletes only the derived index. Pro seats may manage linked client Members under paid coverage but cannot create Administrators or change Company settings. The original zero-Administrator Pro client pattern remains supported.

## Work still required before live commercial deployment

- Pro Company creation stores its contact email as an unverified backup address; an outbox-backed verification service can make a new address authoritative. Initial-email verification is not yet enforced, and backup request/download delivery has no cloud endpoint or production email transport.
- Scheduled downgrade transitions when a trusted renewal event arrives, but a general period-end scheduler and a production-safe cleanup worker are not implemented. The local cleanup proof is hard-guarded to demo emulators; it must not run against real development Companies. Current source enforces a precise hosted-content deadline on Memberships independently of cleanup; live rollout still requires an authorized backfill and coordinated deployment.
- Upgrade and extra-seat events record provider-neutral proration quotes from the term dates and snapshotted development prices. No provider-invoice adapter, subscription ledger reconciliation, or webhook authentication exists. Real prices and paid Company tier ceilings need product decisions.
- Materialized Pro-seat access still needs larger team/company transaction-limit and transfer-race tests. The isolated commercial-convergence branch now tests ordinary Membership overlap and revision/SDS reads after seat removal. New Pro Company backup/contact email enforcement remains outstanding.
- The backup importer now has a native Windows service foundation on the isolated commercial-convergence task branch. It validates a v2 package (with legacy v1 read compatibility), creates a separate migrated SQLite/SDS workspace, verifies hashes/relationships, and atomically renames the staged directory to active. It rejects an already active restored workspace rather than merging. The native UI selects the separate restored workspace for authoring, backup and guarded publication; cloud backup delivery and cloud restore remain unimplemented.
- A separate read-only native inspection command can recheck an activated restored workspace's SQLite integrity, Company identity, SDS ownership, SDS size and SHA-256 against the saved activation descriptors. The Windows service checks Manager/Administrator access and backup eligibility before invoking it. This detects post-activation SDS corruption in v1 and v2 local restores; it does not make the restored workspace the active authoring database. The local descriptor sidecar is not a cryptographic signature against someone able to edit both the workspace and sidecar.

## Commercial/workspace convergence source milestone (not deployed)

`work/commercial-lifecycle-convergence-2026-09-26` began at `origin/main` `30fa9fd2ca6d46d1892259340c165b3e7ff57157`. It adds stricter provider-neutral event transitions and duplicate-ID payload checks, Company-scoped coverage resolution shared by backend operations and status diagnostics, an emulator-only cleanup dry-run using the same eligibility decision as the claiming transaction, and a native restore foundation. Backup v2 includes `schemaVersion: 3` (the minimum SQLite migration containing authoring integrity metadata) and a hash of sorted SDS descriptors; older v1 packages remain readable. The restore service requires live Manager/Administrator membership, active Company context and authoring coverage, then stages a new workspace under app-managed `restored-workspaces`. It never overwrites the primary authoring database. See [work resume](WORK_RESUME_COMMERCIAL_LIFECYCLE.md) for validation and remaining work.

The Windows UI selects primary or distinct restored workspaces. Native session tokens isolate SQL, SDS and journals; access refresh closes and reopens the same workspace when effective permissions change. Restored publication passed integrated native/emulator acceptance and is enabled. Restoration never merges into an existing Company database. Production billing/webhooks, production email, cloud backup delivery, scheduled cleanup, and real-cloud security denial acceptance remain pending.

A subsequent cross-language fixture proves that a deterministic small Company package produced by the JavaScript backup exporter can be imported by the actual native Rust migration/SQLite/SDS path. The native layer independently verifies the v2 SDS descriptor hash and persists `restore-manifest.json` alongside the activated separate workspace.

The next emulator checkpoint adds a paid-grace denial matrix: published hazard read and backup eligibility remain, while authoring, settings, invitations, publication and new Company creation are blocked. An immediate Pro-to-Company billing "upgrade" is rejected in favor of the scheduled downgrade path, and coverage transfer is restricted to the audited Company transaction rather than a standalone billing event.

Company Administrators may now change the **direct** Membership embedded beneath a Pro seat's inherited Manager index. Removing that direct Membership retains inherited Manager access while the Pro seat remains active. Explicit Administrator promotion updates the effective role and count; demotion returns to inherited Manager. The emulator verifies those transitions and that seat removal restores a remaining direct Member role. A stale/mismatched Pro-seat index is denied.

Ordinary billing renewal now uses a persisted calendar anchor. This prevents a January 31 monthly term from drifting to March 28 after February clamps to the 28th; it renews March 31. Leap-day annual anchors similarly return to February 29 in leap years. Synthetic payment recovery keeps its existing full-term restart semantics and starts a new anchor. Existing already-renewed records lacking the anchor can only use their current term start as a compatible fallback.

Scheduled Pro-to-Company downgrade now removes every obsolete inherited Pro Membership in the retained Company when that Company already has an Administrator, including the selected billing owner's inherited Manager index. Direct Memberships survive. If no Administrator exists, the selected active authenticated member is promoted instead. Emulator Rules tests verify that an inherited-only owner loses Company read access after downgrade while a former Pro seat keeps its direct Member role.

Before Pro seat changes or the retained-Company Membership changes of a scheduled downgrade, the trusted billing transaction rechecks the Company's current active coverage owner. This prevents a stale subscription Company list from granting inherited Membership to a transferred or ending Company. Legacy coverage documents with no explicit `state` remain active when their owner still matches; explicit ending/deleting states are denied. Emulator tests exercise mismatch and retry with the same synthetic event ID.

The frozen branch `frozen/commercial-entitlement-v1-2026-09-25` records this validated local/emulator foundation. It is not a claim that billing, production email, cloud backup delivery, or cloud cleanup have been deployed. Never repoint this or any earlier frozen branch.
